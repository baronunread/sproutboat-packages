toolchain (alpha 21 line): P14 pins the runtime globals an app may use to the template's (sproutd issue 97). Porffor builds `node/internal/globals.js` from the runtime globals a program references, in first-use order, so a free `performance`, `process`, `Buffer`, `setImmediate` or `MessageEvent` in app code reordered its installs and, through their import edges, the order of every node unit behind them: an `abi_rejected` for an ordinary program. With `SB_GLOBALS_PIN` set (a JSON array of names), the module installs exactly that array in that order, and a free reference to any other runtime global fails the compile with `<name> is not available in the shared generation`. The names a compile would install are left in `globalThis.__sbGlobalsUsed`, which a template build records as the pin. P4 now also drops the dotted members of an object the prelude owns (`process.stdin` when the prelude assigns `globalThis.process`). Nothing changes without `SB_GLOBALS_PIN`, so standalone builds are as before.

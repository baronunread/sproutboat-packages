Durable Objects follow workerd more closely from compatibility date 2026-11-04; earlier dates answer as before.

- `alarm(alarmInfo)` gets `{ retryCount, isRetry }`. The count lives in the prelude, per object and scheduled time (the broker, the embedded timer and sproutd all deliver through it), and starts over when a run succeeds or the alarm is set for a new time. A failed alarm now answers the broker's trigger with 500 instead of 204, so the broker retries it (it used to treat the failure as delivered).
- `ctx.storage.sql.exec()` runs every statement of a script and returns the last one's cursor, takes parameters only in the last statement, refuses an empty script, and gives workerd's errors for the statements its authorizer refuses (other PRAGMAs, ATTACH, temporary tables, VACUUM, `sqlite_version()`). Bindings coerce as workerd's do (a boolean binds as the text "true", `undefined` as NULL, a BigInt is a TypeError). A cursor's iterator is a new iterator over the same rows.
- `deleteAll()` on a SQLite-backed object drops its tables, views and triggers as well as its keys.
- `ctx.storage.kv` (the synchronous key-value API); `getCurrentBookmark`, `getBookmarkForTime` and `onNextSessionRestoreBookmark` exist and reject (point-in-time recovery is not available); `ctx.abort()`; `ctx.props`.
- Concurrent `storage.transaction()` calls on one object run one after another, so a read-modify-write counter no longer loses updates. `txn.deleteAll()` throws as workerd's does. A transaction used after `txn.rollback()` or after its closure finished rejects with workerd's messages ("Cannot get() on rolled back transaction", "Cannot call put() on transaction that has already committed: did you move `txn` outside of the closure?"); `rollback()` itself stays allowed.
- Structured clone in storage keeps shared and circular references, restores Error subclasses (`RangeError`, ...) and invalid Dates.
- `storage.get([...])` returns its Map in key order; `put({ k: undefined })` skips the entry; `put(["a", 1])` and `put()` throw as workerd's do; `list()` refuses `start` with `startAfter` and takes a fractional `limit`; `setAlarm()` refuses NaN, an invalid Date, a time at or before 0, and a class with no `alarm()` method.
- `DurableObjectId` is a class (`constructor.name`, `instanceof`), `id.equals()` and `namespace.get()` refuse what is not an id, `blockConcurrencyWhile()` refuses a non-function.

Porffor alpha 19 is gone, with its patch chain. The standalone build took its server from a patched alpha 19 tree (the uWebSockets shim, the web classes and the HTTP/1.0 edit) and acquired that tree on every machine that built a standalone binary; those sources are now vendored as first-class files in `a21/standalone-server/` (a provenance header on each, hashes in `sources.json`): `uws-shim.cpp`, `web-classes.js` and `uws-patches/` (upstream Porffor's two uWebSockets patches and sproutboat #236's HTTP/1.0 edit, as unified diffs against uWebSockets `360c276`, applied by a dependency-free applier). They are byte for byte what the alpha 19 chain produced: the shim, the rewritten shim, the web classes and the whole patched uWebSockets `src` tree were compared with it (`scripts/standalone-sources.ts`), and a CI step re-checks the hashes and the patched uWebSockets tree on every PR. A standalone binary's source inputs are identical to before.

Removed: `ensurePorffor`, `ensurePorfforPatched` and every `patch…` pass, `PORFFOR_CHANNEL`, `PORFFOR_COMMIT`, `PORFFOR_COMMIT_FULL`, `PORFFOR_ARCHIVE_*`, `porfforVersion`, `cachedPorfforRoot`, `PATCH_FINGERPRINT` and the `./pin` and `./patch` entry points, the vendored alpha 19 tarball (`porffor-0c135ce.tar.gz`), the alpha 19 native tests, and the trusted-restore native bytes ABI (`--sb-native-bytes-v1`, `NATIVE-BYTES.md`; restore returns as a CLI command). `SPROUTBOAT_PORFFOR_CHANNEL=alpha-19` is now an error that says it is no longer supported, like alpha 21 to 23. `StandaloneChannel` is `"alpha-24"`; `STANDALONE_FALLBACK_CHANNEL` is gone. `composeStandaloneA21(generated)`, `standaloneShimSource()`, `patchUwsHttp10(uwsDir)` and `buildStandaloneA21` no longer take an `alpha19Root`; `ensureHostUws()` takes no argument and lives in `standalone-server` (same `~/.cache/porffor/deps/uWebSockets-<commit>` cache). `alpha19WebClasses` is `standaloneWebClasses()`. `PorfforToolchainError` moved to `a21/acquire`. The package root re-exports `./a21`, `deps` and `fetch-pinned`.
